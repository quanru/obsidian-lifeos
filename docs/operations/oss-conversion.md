# 开源版付费转化观察

本轮先完善设置里的场景对照，保留固定来源参数 `source=lifeos-oss-settings`。插件不记录曝光、点击或活跃情况，不生成用户 ID，不发送笔记、标签、路径或配置。只有用户主动点击链接才打开官网。

## 产品边界

开源版的记录、任务录入、主题组织、基础查询应完整可用。Dataview 是查询所需依赖，不能用依赖报错推销 Pro。创建主题、保存记录、查看空结果时不插入购买弹窗，不设置记录数量或使用期限限制。

升级说明集中在「使用与升级」页，场景对照默认折叠。分别说明日历排期、长列表搜索与筛选、主页工作流的用途。Pro 已有的基础能力不必全部保留为收费差异；比较应围绕用户完成工作时节省的操作。

AI 不属于单买 LifeOS Pro 的承诺：需要独立 DeepAsk 和用户自己的受支持模型服务或 CLI。后续产品边界调整时，同时更新插件文案和官网。

## 观察口径

本轮没有上线统计服务或改动订单系统。以下为发布后的人工复盘流程，不能把它写成已经实现的完整归因。

| 指标                   | 数据来源与限制                                                                                 |
| ---------------------- | ---------------------------------------------------------------------------------------------- |
| 来自设置入口的官网访问 | 在现有网站报表确实支持 `source` 参数时读取；若不支持则填「不可得」。固定参数本身不会生成统计。 |
| 明确来自开源版的订单   | 仅使用已有、用户自愿提供的来源信息；没有来源的订单归为「未知」，不推断。                       |
| 官网总访问、订单、退款 | 使用已有汇总报表，同期价格、促销和渠道变化一并记录；不导出个人订单信息到开源仓库。             |
| 开源活跃用户 → 购买率  | 当前不可得。下载量、安装量和官网访问量均不能代替活跃用户。                                     |

正式发布前记一次基线，发布后每周记录一次，连续观察四周。日期、版本、上述汇总数量、来源是否完整、同期促销以及用户自愿反馈记入私有运营台账。缺失数据写「不可得」，不能填 0。

只有访问与订单采用同一来源、时间窗、去重口径且确实能关联时，才计算入口到购买的转化率；否则分别报告访问和订单，不能硬凑比例。单次访问与跨设备购买也不能直接配对。

若购买减少，先核对流量、促销、价格和来源缺失，再结合用户反馈判断。若用户看了对比仍不理解 Pro 的用途，先改示例和说明；不要直接削弱已免费提供的功能。没有足够样本时维持现有边界，不宣称改动已经提高转化。
